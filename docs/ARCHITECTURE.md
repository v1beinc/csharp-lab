# Архитектура и обоснование

## Решение для сдачи

Браузер → слой интерфейса → движок тестирования → репозиторий вопросов.
Репозиторий выбирает встроенный банк или проверенную копию CSV.
Google Таблицы → публичный CSV по HTTPS при открытии сайта → валидация → локальный банк.
Общий URL задаётся в dist/config.js; без него доступен явно обозначенный деморежим. При ошибке загрузки без копии источника тесты заблокированы.
Попытка → подсчёт результата → localStorage → экспорт TXT/JSON.

Сам предмет тестирования — C#. Реализация сайта на JavaScript не мешает проверять C#, если преподаватель не требует ASP.NET. Такой вариант дешевле размещать, проще передать и запустить. Разделение движка и интерфейса позволяет позднее заменить источник данных серверным API.

## Если требуется ASP.NET или настоящая аттестация

Рекомендуемая следующая архитектура (в этой поставке не реализована):

Адаптивный клиент → ASP.NET Core Web API → PostgreSQL.
Google Sheets API → фоновый импорт на сервере → валидация и версия банка → PostgreSQL.

Таблицы: Topics, Questions, QuestionVersions, Options, TestSessions, SessionQuestions, Answers, Users, Groups. При создании попытки фиксируется версия вопроса, поэтому последующее редактирование таблицы не меняет старые результаты.

API: GET /topics, POST /sessions, GET /sessions/{id}/next, POST /sessions/{id}/answers, POST /sessions/{id}/finish, GET /me/results. Правильный ответ клиенту не передавать до момента, разрешённого режимом. Время экзамена, проверка ответов, выбор сложности и оценка выполняются сервером. Сервер игнорирует присланные клиентом итоговые баллы.

Роли: студент и преподаватель. Авторизация через защищённую серверную cookie; проверка принадлежности каждой сессии на сервере. Преподаватель видит ведомость своей группы и запускает импорт. Ключ доступа Google хранится только на сервере; таблица может быть закрытой. При сбое импорта остаётся последняя корректная версия банка.

Размещение: Docker-контейнер ASP.NET Core на VPS или PaaS с поддержкой .NET и управляемый PostgreSQL. HTTPS, резервные копии, переменные окружения для секретов. Это отдельное расширение: потребует аккаунта хостинга, подключения базы и требований к персональным данным.

## Почему не писать результаты прямо в публичную Google Таблицу

Публичная таблица удобна как редактор учебного контента. Прямая запись результатов из браузера потребовала бы раскрыть права записи или принимать подделанные результаты. Для общей ведомости нужен сервер, который проверяет попытку и затем сохраняет результат.
